# 实验设计与验收标准

本页把课程代码变成可报告的研究矩阵。原则是分别测检索、规则选择、组合、决策和轨迹效率，不能只报最终分类准确率。

## 指标分层

| 层级 | 指标 | 说明 |
|---|---|---|
| 检索 | Recall@5/10、Precision@5/10、MRR | gold canonical rule 是否进入候选 |
| 反思 | 查询改写前后 F1 差、成功率 | 反思是否真的改善召回，而非只生成漂亮文字 |
| 组合 | canonical precision/recall/F1、压缩率、冲突识别率 | 是否正确去重和过滤跨类噪声 |
| 决策 | accuracy、macro-F1、rule compliance、evidence coverage | 类别、规则和证据都要正确 |
| Agent | 完成率、无效动作率、平均轮数、环境总奖励 | 协议与交互效率 |

## 最小对照矩阵

| 编号 | 检索 | 反思 | 组合 | 决策模型 |
|---|---|---|---|---|
| A0 | 无 | 无 | 无 | 只读新闻 |
| A1 | 无 | 无 | 无 | 把全部规则塞进上下文 |
| A2 | BM25 Top-1 | 无 | 无 | 新闻 + 单规则 |
| A3 | Hybrid Top-8 | 无 | 无 | 新闻 + 原始候选 |
| A4 | Hybrid Top-8 | 无 | 结构化组合 | 新闻 + canonical rules |
| A5 | Hybrid Top-8 | 查询改写 | 结构化组合 | 动态多轮 Agent |

`evaluate_pipeline.py` 已实现确定性 A0～A4 的简化版本。A5 必须用 `evaluate_agent.py` 对真实模型轨迹评测。

## 训练消融

固定随机种子、数据划分、LoRA rank、生成温度和采样数，只改一个变量：

1. SFT 轮数：1、3、5。
2. GRPO 轮数：1、2、3。
3. 任务：只训练 decision；retrieve+compose+decision 混训；两阶段课程训练。
4. 奖励：仅最终分类；分类+协议；全部五个自定义奖励；自定义奖励+gym reward。
5. 反思：删除 reflect；固定必须反思；由策略决定是否反思。
6. 组采样：4 对 8，检查 reward 标准差和显存开销。

每个设置至少三个随机种子。课程单次运行只能用于流程验证，不能形成统计显著性结论。

## 训练验收

正式结果至少满足：

- 训练和验证数据不重叠，checksums 已保存。
- GRPO rollout 能出现非零组内 reward 方差。
- 解析成功率、无效动作率和每类准确率单独报告。
- 抽查失败轨迹，区分检索失败、组合失败、协议失败和决策失败。
- 与同一 SFT checkpoint 做训练前后配对评测。
- 报告 GPU、软件版本、峰值 HBM、轮数、步数和实际运行时间。

## 当前待改进点

1. 规则 gold 是标签和关键词生成的弱标注，需人工复核子集。
2. 哈希向量只是教学基线，需替换成真实 embedding 并重新建索引。
3. 规则组合器当前是确定性版本选择与冲突报告，可增加可训练 Composer。
4. 最终决策仍只有四个粗标签；当前 47 条 canonical 规则已经提供多标签细粒度策略空间，但若研究细类别分类准确率，仍需增加人工复核的层次标签，不能直接把规则 ID 当作类别真值。
5. 当前环境最多六轮，其中专家最短轨迹为三到四轮；后续可增加可变调用预算和工具价格。
