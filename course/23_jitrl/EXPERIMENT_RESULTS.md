# JitRL 实测报告

## 结论

当前 Qwen3.5-0.8B-Base 上的核心复现成功。JitRL 没有更新任何模型参数，却把多阶段任务后 10 局平均成功率从静态策略的 **0%** 提高到 `beta=8` 时的 **80%**；100 局总体成功率从 **1.0%** 提高到 **73.4%**。

这只能证明核心机制在本课教学环境中生效，不能等同于复现论文的 Jericho/WebArena 最终分数。

## 正式设置

```text
模型：Qwen3.5-0.8B-Base
加载接口：swift.get_model_processor
回合数：100
随机种子：11、22、33、44、55
候选动作数：3
阶段数：4
gamma：0.5
top-k：10
Jaccard 阈值：0.95
temperature：0.8
未见动作概率 lambda：0.05
乐观强度 alpha：5.0
```

## 主要结果

下表均为 5 个种子的平均值：

| 策略 | 100 局成功率 | 前 10 局成功率 | 后 10 局成功率 | 平均奖励 |
|---|---:|---:|---:|---:|
| 静态冻结策略 | 1.0% | 0.0% | 0.0% | -0.706 |
| JitRL，beta=2 | 46.0% | 20.0% | 50.0% | 1.395 |
| JitRL，beta=4 | 68.6% | 30.0% | 74.0% | 2.303 |
| **JitRL，beta=8** | **73.4%** | **40.0%** | **80.0%** | **2.485** |

`beta=8` 各随机种子的总体成功率为 71%、71%、73%、75%、77%；后 10 局成功率为 70%、90%、70%、80%、90%。提升在所有种子上都出现，不是单个随机种子的偶然结果。

## 探索概率对照

另运行 `lambda=0.35` 的高探索实验：

| 策略 | 100 局成功率 | 前 10 局成功率 | 后 10 局成功率 |
|---|---:|---:|---:|
| 静态冻结策略 | 1.0% | 0.0% | 0.0% |
| JitRL，beta=4 | 49.6% | 22.0% | 50.0% |
| JitRL，beta=8 | 50.4% | 26.0% | 50.0% |
| JitRL，beta=12 | 49.4% | 26.0% | 48.0% |

高探索会不断给 top-k 中没有出现的动作附加乐观优势。即使 Agent 已找到正确协议，它仍可能主动试错，所以后期成功率停在约 50%。确定性任务更适合 `lambda=0.05`；环境变化频繁时可以提高 lambda，但应接受短期性能下降。

## 性能与显存

96 个有限决策提示用一个 batch 完成基础 logits 预计算。正式稳定实验峰值显存为 **2.255 GiB**，程序内计时约 **12.2 秒**；首次冷启动还会额外花时间初始化 ms-swift 和读取模型文件。

JitRL 的目标本来就是推理期学习，因此不会为了“占满显存”创建梯度、优化器状态或模型副本。这里提升速度的正确方式是批量预计算冻结策略，而不是人为增加显存占用。

## OpenAI 兼容 API 实测

在同一台机器上用 ms-swift v4.4.3 标签源码（上游运行时版本字符串为 `4.5.0.dev0`）和 vLLM 0.26.0 部署当前 Qwen3.5-0.8B-Base，然后使用 `constrained_logprobs` 模式通过真实 HTTP 请求取得候选动作分数。服务端共处理 96 个不同状态，每个请求生成 1 个动作编号并返回 3 个合法编号的 logprobs。

设置仍为 100 局、5 个随机种子、`lambda=0.05`：

| API 策略 | 100 局成功率 | 前 10 局成功率 | 后 10 局成功率 |
|---|---:|---:|---:|
| API 静态冻结策略 | 0.8% | 2.0% | 0.0% |
| API JitRL，beta=2 | 46.6% | 24.0% | 48.0% |
| API JitRL，beta=4 | 69.4% | 32.0% | **84.0%** |
| API JitRL，beta=8 | **74.2%** | **46.0%** | 78.0% |

API 客户端从健康检查、96 次并发打分到全部模拟完成，程序内计时约 6.46 秒。它只调用 Chat Completions，不创建优化器、不调用 backward；远程参数是否固定无法由客户端读取，必须由部署端保证。

完整原始结果位于：

```text
outputs/23_jitrl_api/run_20260809T041522Z/result.json
```

Git 留档摘要为 `results/jitrl/summary_api_100ep.json`，接入方法见 [API_DEPLOYMENT.md](API_DEPLOYMENT.md)。
