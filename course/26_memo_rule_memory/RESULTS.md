# MeMo 规则记忆真实训练与审核实验

本页只记录本机真实运行结果。完整权重和逐条轨迹位于被 Git 忽略的
`outputs/26_memo_rule_memory/`；可提交的数值摘要位于 [results](results/)。本课复现的是
[MeMo 论文](https://arxiv.org/abs/2605.15156) 的核心“Memory 参数承载知识、冻结
Executive 按需询问”思路，并针对内容审核增加 Grounding、稳定 ID 注册表和确定性规则执行器。
它不是论文大模型配置或公开 benchmark 绝对分数的逐项复现。

## 实验设置

| 项目 | 本次实测值 |
|---|---|
| 基础模型 | `Qwen3.5-0.8B-Base`；Memory 与 Executive 各使用一个实例 |
| 训练框架 | ms-swift 官方 `v4.4.3` 源码环境 |
| GPU | 1 × AMD MI308X，191.69 GiB HBM |
| 规则 | 80 条；政治、财经、体育、计算机各 20 条 |
| Memory 数据 | 680 条训练问答、200 条未见措辞留出问答 |
| 审核数据 | 120 篇互不重复新闻：80 单规则、20 绑定例外、20 跨规则 |
| 训练方式 | 全参数 SFT，3 轮、33 step、batch 64、BF16 |
| 优化参数 | LR `2e-5`、constant warmup 5%、weight decay `0.01`、grad norm `1.0` |
| 序列长度 | 上限 768；真实最大 311 token，无截断样本 |
| 推理设置 | `temperature=0`，Memory 最多 512 token，Executive 最多 384 token |

Qwen3.5-0.8B-Base 在 ms-swift 中共有 852.99M 参数，本次可训练 752.39M（88.21%）；未训练的部分
主要是该架构中被冻结的视觉组件。训练共 162.22 秒，峰值逻辑 HBM 102.57 GiB。`memory(GiB)`
来自训练器统计，不等同于 `rocm-smi` 的外部物理峰值。

## 三轮训练与动态选模

训练 loss 从首步 3.517 降到末步 0.0257。三轮 teacher-forcing 验证结果依次为：

| 轮次 | checkpoint | eval loss | token accuracy |
|---:|---:|---:|---:|
| 1 | 11 | 0.21843 | 93.67% |
| 2 | 22 | 0.06173 | 97.73% |
| 3 | 33 | **0.03169** | **98.97%** |

仅凭 token accuracy 不能证明模型真的记住规则，所以又让 Base 与三个检查点分别生成 200 条
未见措辞答案：

| 模型 | 格式率 | 决策准确率 | 精确规则 ID F1 | 事实锚点覆盖 |
|---|---:|---:|---:|---:|
| 原始 Base | 18.50% | 10.00% | 0.00% | 0.00% |
| checkpoint-11 | 100.00% | 64.50% | 2.67% | 32.83% |
| checkpoint-22 | 100.00% | 85.50% | 40.50% | 61.08% |
| **checkpoint-33** | **100.00%** | **96.00%** | **72.25%** | **83.42%** |

因此正式审核选择 `checkpoint-33`。这里的规则 ID F1 比决策准确率低，说明 0.8B Memory
常能记住处置与规则语义，却会把数字序号写错；这是生成式知识存储不能只看答案大意的原因。

## 120 条新闻的七组对照

下表统一使用冻结的 Base Executive。`MeMo 分阶段+确定性` 除外：它让 LLM 负责回忆规则，
最终由显式规则执行器绑定例外和比较优先级。百分比均来自完整 120 条，不是抽样示例。

| 方法 | 决策准确率 | Macro-F1 | 规则 F1 | 单规则 | 绑定例外 | 跨规则 | 平均最终输入字符 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 无规则 | 59.17% | 42.62% | 0.00% | 52.50% | 70.00% | 75.00% | 701 |
| 全量 80 规则 | 30.00% | 15.38% | 0.33% | 20.00% | 100.00% | 0.00% | 8162 |
| BM25 Top-5 | 40.83% | 35.24% | 27.37% | 35.00% | 100.00% | 5.00% | 1973 |
| MeMo 单轮 | 70.00% | 67.82% | 74.31% | 96.25% | 0.00% | 35.00% | 894 |
| MeMo 分阶段 + Base Executive | 76.67% | 74.44% | 82.08% | 96.25% | 0.00% | 75.00% | 1399 |
| **MeMo 分阶段 + 确定性执行** | **97.50%** | **96.53%** | **82.08%** | **96.25%** | **100.00%** | **100.00%** | 1166 |
| Oracle 规则 + Base Executive | 85.00% | 84.24% | 88.06% | 100.00% | 90.00% | 20.00% | 1032 |

这组结果支持三个结论：

1. 参数化 Memory 有真实作用。单轮 MeMo 比无规则高 10.83 个百分点，并把最终 Prompt 从全量规则的
   8162 字符降到 894 字符。
2. 小 Base Executive 不是可靠的规则解释器。即使直接给金规则，跨规则准确率也只有 20%；它还经常
   漏掉 `<audit>` 外层标签。生产中适合让 LLM 获取规则、让确定性代码执行高风险处置。
3. 多轮不等于把同一问题问三遍。有效版本先从新闻中 Grounding 发布片段，再把同一附言中的风险、
   例外或第二条规则拆成独立请求，最后合并候选、确认事实并检查冲突。

`format_rate` 接受合法裸 JSON，`wrapper_rate` 才要求严格的 `<audit>JSON</audit>`。冻结 Base 在
MeMo/Oracle 方案中通常能生成可解析 JSON，却几乎总漏掉外层标签；报告没有把二者混成一个指标。
确定性执行器没有最终 LLM Prompt，表中最后一列对它表示内容与 Memory 上下文的字符总量。

## 两个必要的控制器改进

### Grounding 与多线索分片

同一个训练后 Memory 和同一个确定性执行器，仅改变输入组织方式：

| 输入方式 | 决策准确率 | 规则 F1 | 单规则 | 绑定例外 | 跨规则 |
|---|---:|---:|---:|---:|---:|
| 完整长新闻直接输入 Memory | 52.50% | 28.61% | 60.00% | 25.00% | 50.00% |
| 先 Grounding，再拆分附言中的独立线索 | **97.50%** | **82.08%** | **96.25%** | **100.00%** | **100.00%** |

Memory 的训练问题只有约 139～311 token，把几百字新闻背景和真正审核线索一起塞入会造成严重干扰。
线上若字段本来已经拆成标题、正文、评论、发布者附言，应直接传目标字段；若只有混合文本，需要先做
可审计的 span extraction，不能把金规则或标签用于 Grounding。

### 稳定 ID 注册表

完整分片实验中，Memory 原始规则 ID F1 为 76.39%，经注册表解析后为 82.08%。注册表只含合法 ID、
领域和唯一语义后缀，例如把不存在的 `POL-04-SALE` 映射为该领域唯一的 `POL-01-SALE`；它不读取规则
正文，也不接触金标签。原始编号保存在 `raw_rule_ids`，两个指标同时报告，不能把后处理冒充模型能力。

## 规则数量扩展探针

使用真实 Qwen3.5 聊天模板，把 80 条规则循环扩展并只改 ID，测得：

| 规则数 | 全规则上下文字符 | 全规则 Prompt token | Memory 请求 token |
|---:|---:|---:|---:|
| 80 | 7,879 | 5,062 | 105 |
| 400 | 39,399 | 23,798 | 105 |
| 800 | 78,799 | 47,218 | 105 |
| 1,600 | 157,599 | 94,058 | 105 |

这是长度探针，不是 1600 条新知识的准确率实验。它验证全量上下文随规则数线性增长，而训练完成后的
Memory 请求不携带规则库、长度保持不变；要证明更大容量仍保持准确率，必须用真正不同的规则重新训练。

## 三个剩余错误

最佳确定性方案只错 3/120，全部属于 `PERSONAL_ADVICE` 的单规则 `REVIEW`：

- 政治“定制规避现场管控路线”被回忆成 `EVASION`；
- 财经“直接给出高杠杆买卖指令”被回忆成 `DANGEROUS_GUIDE`；
- 计算机“针对未授权目标定制漏洞利用步骤”被回忆成 `DANGEROUS_GUIDE`。

三条都被更严格地判为 `REJECT`，没有危险的误放行，但暴露出相邻规则边界不足。下一轮数据应增加
`PERSONAL_ADVICE` 与 `EVASION/DANGEROUS_GUIDE` 的困难负例和成对辨析，而不是盲目增加训练轮次。

## 上线边界

- 这 80 条规则和附言是合成教学数据，97.5% 不能外推为真实业务准确率；上线前必须由法务/政策人员确认
  条件、例外和优先级，并用双人标注的真实时间外测试集重评。
- Memory 留出问答与审核集没有相同完整问题或新闻，但共享同一批规则及部分规则线索措辞；它验证的是
  规则记忆和系统链路，不是对全新政策概念或自由改写的泛化能力。
- Memory 更新规则需要重生成问答、训练新版本并跑固定回归集；本课没有实现在线增量删除。规则过期时按
  当前流程从源规则库删除并发布新 Memory 即可。
- 低置信、无有效 ID、ID 注册失败或 Memory 多阶段矛盾时必须降级 `REVIEW`，不能自动 `PASS`。
- 阿里云等 API 可以直接替代 Executive；若要把 Memory 也改成 API，远程端必须部署本课训练后的 Memory
  权重，不能拿通用聊天 API 冒充已经记住私有规则的 Memory。密钥只从环境变量读取。
