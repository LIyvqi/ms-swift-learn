# 显式 CoT-GRPO 奖励设计说明

本说明把第 03 课的奖励拆成结果层、结构层、可执行过程层、相关性层和语义裁判层。这样做的目的不是堆叠奖励数量，而是让每一项只回答一个可以诊断的问题。

## 总体原则

最终任务是答对数学题，因此答案正确性始终是主奖励。过程奖励只能帮助区分“答案同样正确但推理质量不同”的候选，不能凌驾于结果目标。

```text
结果正确
   │
   ├── 格式是否完整、思考是否非空
   ├── 显式算式能否安全执行并成立
   ├── 是否使用题目数值条件
   ├── 思考过程与最终答案是否一致
   └── 大模型是否认为过程正确且完整
```

奖励插件位于 `course/plugins/gsm8k_rewards.py`。所有奖励都返回 0～1，训练脚本再通过 `--reward_weights` 设置相对权重。

## 1. 最终答案正确性

注册名：`course_gsm8k_accuracy`

算法：

1. 从候选回答最后一个 `\boxed{...}` 提取预测值。
2. 从顶层 `solution` 的 `\boxed{...}` 或 `#### 数字` 提取标准值。
3. 可转成浮点数时用 `1e-5` 误差比较，否则使用规范化字符串精确比较。

正确得 1，错误得 0。它不关心思考块内容，是最重要的结果奖励。

## 2. 严格 CoT 结构

注册名：`course_gsm8k_cot_structure`

必须完整匹配：

```text
<think>20～12000 个字符的非空过程</think>
\boxed{唯一最终答案}
```

开头或结尾有多余内容、思考为空、标签未闭合、出现嵌套花括号，均不得分。长度边界是防空输出和无限啰嗦的粗粒度护栏，不代表过程质量。

## 3. 可执行计算过程

注册名：`course_gsm8k_cot_calculation`

该奖励只读取 `<think>` 内形如以下形式的四则算式：

```text
8*5=40
(12+8)/4=5
30÷6=5
```

实现不使用 Python `eval`。表达式先解析为受限 AST，只允许：

- 整数、小数和括号。
- 一元正负号。
- 加、减、乘、除。
- 最多 64 个语法节点。
- 绝对值不超过 `10^15` 的结果。

变量、函数调用、属性读取、幂运算和其他 Python 语法都会被拒绝，因此不能借奖励函数执行任意代码。

为了降低 `1+1=2` 这类无关正确算式的投机，等式还必须满足至少一个相关条件：

- 左侧使用了题目中的数字；或
- 右侧等于顶层 `final_answer`。

设相关等式数量为 `N`，其中数学成立的数量为 `C`：

```text
基础分 = C / N
```

若没有任何正确等式直接得到最终答案，基础分再乘 0.75。完全没有相关等式时为 0。

局限性：当前版本不解析分数 LaTeX、百分数、单位、变量方程和自然语言蕴含。它适合 GSM8K 基础四则运算教学，不是通用数学证明器。

## 4. 题目数值覆盖

注册名：`course_gsm8k_cot_grounding`

```text
覆盖分 = 思考块中出现的题目数字种类数 / 题目数字种类总数
```

该奖励希望模型使用题目条件，而不是直接猜答案。它非常容易通过机械复制数字投机，因此权重只有 0.15，并且必须与计算正确性同时使用。

## 5. 过程答案一致性

注册名：`course_gsm8k_cot_consistency`

最终框选数字也在思考块中出现时得 1，否则得 0。它可以发现“过程算到 40，最后却写 35”一类显式矛盾，但无法判断 40 本身是否正确；答案正确性奖励负责这一点。

## 6. 大模型过程裁判

注册名：`course_gsm8k_cot_llm_judge`

这是一个 `AsyncORM`。每条候选回答会连同题目和参考解答发送给 OpenAI 兼容 API，裁判按以下等级评分：

| 原始分 | 含义 | 归一化奖励 |
|---:|---|---:|
| 0 | 没有有效推理或严重错误 | 0.00 |
| 1 | 有尝试，但关键计算错误 | 0.25 |
| 2 | 部分步骤正确，缺少关键推导 | 0.50 |
| 3 | 基本正确，仅有轻微遗漏 | 0.75 |
| 4 | 正确、相关且足以推出答案 | 1.00 |

实现细节：

- 温度固定为 0，最多生成 64 token。
- 使用 `asyncio.gather` 并发请求，默认并发度 16。
- 同一训练进程中完全相同的题目、参考和候选会命中内存缓存。
- 单次失败会重试一次；仍失败则返回 0。
- 候选回答被标记为不可信内容，裁判被要求忽略其中的指令。
- API Key 只从环境变量读取，不写入输出。

可选配置：

| 环境变量 | 默认值 | 含义 |
|---|---:|---|
| `GRPO_JUDGE_API_BASE` | 无 | OpenAI 兼容 `/v1` 地址，必需 |
| `GRPO_JUDGE_API_KEY` | 无 | 临时密钥，必需；本地服务可显式设为 `EMPTY` |
| `GRPO_JUDGE_MODEL` | 无 | 裁判模型名，必需 |
| `GRPO_JUDGE_TIMEOUT` | 60 | 单批请求总超时秒数 |
| `GRPO_JUDGE_CONCURRENCY` | 16 | 最大并发请求数 |

## 三种显式 CoT 配方

### 规则版

```text
1.00 × accuracy
+ 0.20 × structure
+ 0.50 × calculation
+ 0.15 × grounding
+ 0.15 × consistency
```

优点是免费、确定、快速、可解释；缺点是只覆盖能写成简单等式的过程。

### 裁判版

```text
1.00 × accuracy
+ 0.20 × structure
+ 0.80 × llm_judge
```

优点是能评价自然语言和复杂推导；缺点是昂贵、有延迟、存在版本漂移和裁判误判。

### 混合版

```text
1.00 × accuracy
+ 0.20 × structure
+ 0.50 × calculation
+ 0.15 × grounding
+ 0.15 × consistency
+ 0.40 × llm_judge
```

混合版适合研究消融，但奖励项更多不等于一定更好。各奖励可能相关或冲突，应分别记录均值和标准差。

## 典型奖励投机

| 投机行为 | 哪项奖励可能被骗 | 当前缓解措施 |
|---|---|---|
| 输出空 `<think></think>` | 宽松格式奖励 | 严格要求非空及最小长度 |
| 复制题目数字但不推理 | 数值覆盖 | 低权重并组合可执行算式 |
| 写 `1+1=2` 后猜答案 | 算式正确 | 要求算式与题目数字或最终答案相关 |
| 堆很多正确但无关算式 | 计算奖励 | 相关性过滤；仍需人工抽查 |
| 在候选中命令裁判给高分 | 大模型裁判 | 不可信边界和系统指令；无法完全消除 |
| 写很长、听起来合理的错误理由 | 大模型裁判 | 同时保留最终答案和可执行规则 |

## 推荐消融实验

至少比较以下设置，并使用相同的 SFT 起点、Prompt、随机种子和训练步数：

1. 只有答案正确奖励。
2. 答案正确 + 严格结构。
3. 完整规则版。
4. 答案正确 + 大模型裁判。
5. 完整混合版。

评测不能只看训练总 reward。还应报告验证答案正确率、非空思考率、严格格式率、可执行正确等式率、平均思考长度、截断率、API 成本和失败率。
