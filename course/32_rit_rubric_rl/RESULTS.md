# 第 32 课 RiT 实测结果

本报告记录 2026-09-02 在当前机器上真实完成的 `Qwen3.5-0.8B-Base` 实验。所有准确率都来自固定 200 条 test 的温度 0 真实生成，不是训练 reward，也不是从金答案回填。

## 1. 实验环境与口径

| 项目 | 配置 |
|---|---|
| GPU | AMD MI308X，191.7 GiB 可用显存 |
| 系统 | Ubuntu 22.04、ROCm 7.2 |
| 模型 | 本地 `Qwen3.5-0.8B-Base` |
| 框架 | ms-swift 4.4.3 本地源码入口；包版本显示 4.5.0.dev0 |
| PyTorch | 2.11 ROCm 开发构建，bfloat16 |
| vLLM | 0.26.0 ROCm，colocate 模式 |
| 训练数据 | BeaverTails train 1600 |
| 验证 / 测试 | validation 200 / test 200，ID 零交集 |
| 类别 | SAFE + 14 个可多选风险类别 |
| 主指标 | `is_safe` 与全部类别有序规范化后完全匹配 |

TRL 会提示其已声明测试的 vLLM 版本较旧，但当前 0.26.0 ROCm 的 SFT、vLLM 采样、GRPO 反向传播和检查点保存均真实成功。该警告需要保留，不代表已经证明所有组合都兼容。

## 2. 实际训练设置

### 显式思维 SFT

- 1600 条 train 全量一轮，200 step。
- LoRA rank 32、alpha 64、dropout 0.05。
- batch 8、学习率 `5e-5`、最大长度 1536。
- 完成时间 4 分 18 秒，峰值显存 52.87 GiB。
- validation loss 0.01852，validation token accuracy 0.9939。

### ORM 与 RiT GRPO

- 两组都从同一个 `checkpoint-200` 开始。
- 每个提示 8 个 rollout，generation batch 16，训练 batch 8。
- 30 step、学习率 `2e-6`、`beta=0.01`、最大 completion 768。
- 每组实际覆盖 30 个训练提示、240 条 rollout；这是缩放机制实验，不是论文 500-step 规模复刻。
- ORM 用时 2 分 40 秒，峰值显存 110.77 GiB。
- RiT 用时 2 分 27 秒，峰值显存 107.41 GiB。

### 无自由思维链的短结构化 SFT

- 同一 1600 条 train 全量一轮，134 step。
- `enable_thinking=false`、`add_non_thinking_prefix=false`。
- batch 12、最大长度 1280、最大生成长度 384。
- 完成时间 4 分 40 秒，峰值显存 54.48 GiB。
- validation loss 0.03187，validation token accuracy 0.9894。
- 短结构化 RiT 另跑了 2-step GRPO 冒烟，102～104 GiB 显存下完成采样、逐字段奖励、反向传播和保存。

## 3. 显式思维主实验结果

| 模型 | Exact | Safety Acc | Macro-F1 | Micro-F1 | 格式率 | 思维均分 | 规则覆盖 | 平均总输出字符 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 格式 SFT | **57.0%** | 72.0% | **35.51%** | **59.64%** | 100% | **0.9333** | **60.5%** | 415.53 |
| SFT + 30-step ORM | **57.0%** | 72.0% | 34.95% | 59.00% | 100% | 0.9325 | 60.0% | 418.46 |
| SFT + 30-step RiT | 56.0% | 72.0% | 34.41% | 58.31% | 100% | 0.9317 | 59.0% | 418.34 |

这次本地 0.8B 实验中，RiT **没有带来提升**：Exact 比共同 SFT 起点和 ORM 都低 1 个百分点，规则覆盖也没有提高。200 条逐样本对比中：

- ORM 相对 SFT 新答对 2 条、答错 2 条，总数不变。
- RiT 相对 SFT 新答对 3 条、答错 5 条，净少 2 条。
- RiT 只改变了 17/200 条贪心输出，30 step 更新幅度很小。

## 4. 为什么本地 RiT 没有效果

最直接的原因是本地 rubric 在 SFT 后几乎饱和，而且与最终正确性高度耦合：

- SFT 的 114 条严格答对样本中，113 条的六项思维分已经是 1.0。
- 只有 1 条“答案正确但证据没有逐字落地”，思维分为 5/6。
- 86 条错误答案中，79 条思维分为 5/6，另有 7 条甚至是 1.0。
- 思维分与 exact correctness 的 Pearson 相关为 0.9194。

因此 `min(R_thinking, R_response)` 在绝大多数 rollout 上退化为 outcome reward：答错都是 0，答对几乎都是 1。训练日志也支持这一点：

| GRPO 日志均值 | ORM | RiT |
|---|---:|---:|
| Outcome reward | 0.6292 | 0.6250 |
| Gated reward | — | 0.6222 |
| Thinking reward | — | 0.9403 |
| rollout 平均 token | 147.21 | 144.88 |
| 零组内方差比例 | 33.33% | 30.00% |

RiT gated 与 outcome 只差约 0.0028，额外学习信号太弱。再增加相同本地模板 reward 的步数，很可能只是放大随机漂移，不足以证明 RiT 有效。

这也解释了官方方案为什么使用独立强模型做语义 rubric：本地规则只能检查“有没有标签、有没有原文片段、有没有边界词”，很难判断证据是否真正支持结论、边界推理是否合理。课程已经实现 OpenAI 兼容的异步独立评审接口，但本轮没有配置外部评审密钥，因此没有伪造 API 实验结果。

## 5. 门控公式确实按设计工作

`audit_reward_design.py` 对 1600 条专家轨迹和可控反例做了真实评分：

| 可控输出 | `min` | 无门控 | `max` | 条件门控 |
|---|---:|---:|---:|---:|
| 专家思考 + 正确答案 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| 空思考 + 正确答案 | 0.0000 | 0.0000 | 1.0000 | 0.0000 |
| 幻觉证据 + 正确答案 | 0.8333 | 0.8333 | 1.0000 | 0.8333 |
| 缺少边界 + 正确答案 | 0.8333 | 0.8333 | 1.0000 | 0.8333 |
| 结构完整 + 错误答案 | **0.0000** | 1.0000 | 1.0000 | **0.0000** |

这证明实现层面的关键性质成立：`min` 门控不会让“写得漂亮但答案错误”的输出拿奖励。它证明的是公式和框架链路正确，不证明当前弱 rubric 能提升泛化。

## 6. 不开启自由 think 的结果

Qwen3.5 在 `enable_thinking=false` 时仍会按模板输出空的 `<think>\n\n</think>` 协议前缀，但其中没有任何 token 内容。修正解析器以允许精确空前缀、继续拒绝非空 think 后，200 条完整结果如下：

| 路线 | Exact | Safety Acc | Macro-F1 | Micro-F1 | 格式率 | 平均输出字符 | 200 条生成用时 | 吞吐 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 显式思维 SFT | **57.0%** | **72.0%** | 35.51% | **59.64%** | 100% | 415.53 | 84.25 秒 | 2.37 条/秒 |
| 短结构化 SFT | 55.0% | 68.5% | **38.79%** | 57.23% | 100% | **285.92** | **52.80 秒** | **3.79 条/秒** |

短结构化路线的变化：

- 平均输出字符减少 **31.19%**。
- 同一 GPU、batch 32 下，整套测试生成时间减少 **37.33%**。
- 吞吐提高 **59.58%**。
- Exact 降低 2 个百分点，Safety Accuracy 降低 3.5 个百分点。
- Macro-F1 反而高 3.28 个百分点，但 Micro-F1 低 2.41 个百分点，说明它没有在所有指标上一致占优。
- 固定格式、证据落地、边界简洁、字段一致和无非空思维链均为 100%；规则完全匹配率为 55%，与 exact 一致。

结论是：**可以不开启自由 think，用少量公开分析字段实现可审计审核**。本轮它显著更短、更快，准确率有小幅代价；适合更看重延迟、审计和可落库结构的场景。它不能被表述为“用结构字段复现了完整长推理能力”。

## 7. Token 长度与容量

真实 tokenizer 审计结果：

| 数据 | p50 | p95 | 最大 | 脚本上限 |
|---|---:|---:|---:|---:|
| 显式 SFT | 842 | 945 | 1087 | 1536 |
| 显式 RL prompt | 688 | 766 | 910 | 1536 |
| 短结构 SFT | 821 | 918 | 1058 | 1280 |
| 短结构 RL prompt | 734 | 812 | 956 | 1280 |

全部 1600 条都没有截断。短结构 RL prompt 略长，是因为 system 对五个字段的 JSON 约束写得更明确；真正节省发生在生成侧。

## 8. 这次复现能说明什么

已经验证：

- 本地 0.8B 模型能用 ms-swift 完成 RiT 所需的 SFT → 8-rollout GRPO → 自定义 ORM → LoRA 保存全链路。
- 论文的二元 rubric、融合、`min` 硬门控和 outcome-only 公平对照都可复现。
- 本地离线 rubric、异步 API rubric、提示注入隔离和严格解析都可用单元测试验证。
- 无自由 think 的五字段扩展可以真实训练和部署，长度与速度收益明确。

尚不能说明：

- 当前 30-step、0.8B、本地模板 rubric 能复现官方更大模型的 benchmark 增益。
- 本地规则检查等价于 Qwen3-235B 语义评审。
- 训练 reward 上升就等于保留集推理能力上升。

下一轮最有价值的实验不是盲目加 step，而是引入独立强评审器或人工小规模过程标签，让“答案正确但证据/规则推理有缺陷”的样本真正出现，再跑至少三个随机种子的 ORM/RiT 对照并报告置信区间。
