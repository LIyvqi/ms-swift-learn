# 第 32 课 RiT 安全审核 Agent 实测结果

本报告只记录真实运行结果。所有模型都使用本地 `Qwen3.5-0.8B-Base`，训练由 ms-swift 4.4.3 执行，推理固定温度 0。完整 checkpoint 和逐条轨迹位于被 Git 忽略的 `outputs/32_rit_rubric_rl/agent/`，仓库只提交可重建的数据、代码和本报告。

## 1. 数据与隔离口径

| 项目 | 数量 |
|---|---:|
| 原始 train / validation / test | 1600 / 200 / 200 |
| active 规则 | 14 |
| train-only 已确认 Case | 141 |
| SFT 专家训练轨迹 | 1600 |
| GYM-GRPO 训练任务 | 1600 |
| 固定隔离测试 | 200 |

规则和案例是两个独立 JSONL。Case 不含 validation/test，训练检索还排除当前 `record_id`。评测器让模型真实执行最多三轮的 `search_rule`、`search_case` 和 `finish`，不是把专家工具结果预先喂给模型。

真实 Qwen tokenizer 对 1600 条 SFT 轨迹的长度审计为：最短 523、P50 1252、P95 2056、最长 2236、平均 1441.55 token；没有样本超过 `max_length=3072`。

## 2. 训练实况

### 2.1 多轮 SFT

SFT 使用全部 1600 条轨迹、1 epoch、batch 6、LoRA rank 32、学习率 `5e-5`：

| 指标 | 实测值 |
|---|---:|
| step | 267 |
| 训练时间 | 593.42 秒，约 9 分 53 秒 |
| train loss | 0.06546 |
| validation loss | 0.02073 |
| validation token accuracy | 99.28% |
| 框架日志显存 | 100.91 GiB |

很低的 token loss 只说明动作格式和专家路线被学会，不能代替真实分类评测。

### 2.2 同起点 GRPO

ORM 与 RiT 都从同一个 SFT `checkpoint-267` 出发，使用相同的 1600 条 RL 数据、30 step、每组 8 个 rollout、生成 batch 16、反向 batch 8、学习率 `2e-6`、`beta=0.01`。唯一主动变化是优化奖励：ORM 用最终精确结果，RiT 用 `min(六项过程均分, 最终精确结果)`。

| 指标 | ORM-GRPO | RiT-GRPO |
|---|---:|---:|
| 训练时间 | 366.56 秒 | 366.11 秒 |
| 框架日志显存 | 166.46 GiB | 166.37 GiB |
| 有 rollout 的日志批次 | 15 | 15 |
| 平均结果奖励 | 0.3333 | 0.3625 |
| 平均过程奖励 | 0.7451 | 0.7715 |
| 平均门控奖励 | 0.3229 | 0.3549 |
| 平均优化奖励 | 0.3333 | 0.3549 |
| 平均组内 reward std | 0.3900 | 0.3993 |
| 零方差批次占比 | 20.00% | 16.67% |
| 平均总生成长度 | 248.35 | 254.52 |
| 平均轮数 | 2.22 | 2.26 |

两组训练都有非零组内方差和真实梯度更新，不是“奖励全零所以没有训练”。

## 3. 200 条隔离测试

| 实验 | 完成率 | 安全准确率 | Exact | 样本 F1 | Micro-F1 | 过程分 | 规则落地 | 案例落地 | 预测 SAFE | 耗时 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| SFT + 两库 | 99.00% | **60.00%** | 35.50% | 44.90% | **52.08%** | **83.08%** | **71.50%** | 57.50% | 18.00% | 312.7 秒 |
| SFT + 空库消融 | 76.00% | 40.00% | 36.00% | 37.95% | 12.90% | 53.92% | 37.50% | 18.50% | 67.50% | 268.6 秒 |
| ORM-GRPO + 两库 | 98.50% | 46.00% | **44.50%** | **45.03%** | 8.74% | 75.83% | 45.50% | **68.00%** | 94.00% | 225.4 秒 |
| RiT-GRPO + 两库 | 98.50% | 46.00% | 44.00% | 44.73% | 6.93% | 75.58% | 44.50% | **68.00%** | 95.00% | 217.9 秒 |

测试集含 89 条 SAFE 和 111 条 UNSAFE，SAFE 占 44.5%。`Exact` 要求安全结论和完整多标签同时正确。样本 F1 对“金标签为空且预测也为空”的 SAFE 样本记 1，因此在模型塌缩为 SAFE 时仍会显得不低；判断风险类别能力应重点看安全准确率和 Micro-F1。

## 4. 外部记忆是否有效

对同一个 SFT checkpoint 关闭两库，模型权重、测试集和生成参数都不变：

| 指标 | 两库相对空库的变化 |
|---|---:|
| 完成率 | +23.00 个百分点 |
| 非法动作率 | -17.99 个百分点 |
| 安全准确率 | +20.00 个百分点 |
| 样本 F1 | +6.95 个百分点 |
| Micro-F1 | +39.18 个百分点 |
| 过程分 | +29.17 个百分点 |
| 规则落地 | +34.00 个百分点 |
| 案例落地 | +39.00 个百分点 |
| Exact | -0.50 个百分点 |

结论是：两库明显改善了轨迹完成、风险识别、多标签质量和真实引用，但没有提高最苛刻的 Exact，反而低 0.5 个百分点。这 1 条样本量级的差异不能证明 Exact 退化，也不能把记忆宣传成全指标提升。

空库时，模型仍按 SFT 习惯调用工具，但拿到空结果后大量无法合法完成；它最后有 67.5% 的样本预测 SAFE。启用真实检索后，预测 SAFE 比例降到 18%，风险多标签 Micro-F1 从 12.90% 升到 52.08%。这支持“收益确实来自外部内容，而不仅是动作模板”的解释。

## 5. 30-step GRPO 为什么失败

ORM 的 Exact 从 35.5% 升到 44.5%，单看这个数很容易误判为强化学习有效。但它把 188/200 条样本预测为 SAFE；RiT 更进一步把 190/200 条预测为 SAFE。由于 test 恰好有 89 条 SAFE，模型接近“总是 SAFE”就能取得约 44.5% Exact。

代价非常明确：

- ORM 的安全准确率从 60% 降到 46%，Micro-F1 从 52.08% 降到 8.74%。
- RiT 的安全准确率也是 46%，Micro-F1 进一步降到 6.93%。
- ORM 每条平均只查 0.045 次规则，RiT 只查 0.035 次；两者几乎都退化成“查一次 Case，然后判 SAFE”。
- RiT 相对 ORM 没有改进：Exact 低 0.5 个百分点，过程分低 0.25 个百分点。

根因不是没有过程量规，而是本实验采用严格二元结果硬门控：不安全样本早期很难一次命中完整多标签，整组 rollout 经常全为 0；SAFE 样本只要空类别正确就更容易产生正 advantage。`min` 门控能阻止错误答案靠漂亮过程得分，却不能凭空为“安全方向正确但标签不完整”的 UNSAFE rollout 制造学习信号。30 step 后，两个目标都利用了更容易的 SAFE 奖励通道。

## 6. 当前应使用哪个 checkpoint

在这组实际实验中，应保留 **SFT + 两库** 作为课程当前最佳 Agent，不应因为 Exact 单项更高就把 ORM 或 RiT checkpoint 当成更好的审核模型。SFT 的安全准确率、Micro-F1、过程分和规则落地都明显更高。

RiT 这次没有产生效果增益。课程复现成功的是：ms-swift 多轮 GYM、两库工具、RiT 三路奖励、硬门控、同起点对照和真实测试闭环；没有复现出论文在更大模型和原任务上的收益。

## 7. 下一轮值得验证的改法

下一轮不要盲目增加 strict GRPO 步数，否则可能把 SAFE 塌缩训练得更牢。建议按顺序做：

1. 在训练监控中加入预测 SAFE 比例和风险 Micro-F1，出现单类塌缩时提前停止。
2. 先用 `0.5 × 安全方向 + 0.5 × 类别 F1` 的稠密结果课程给 UNSAFE rollout 部分反馈，再切回 strict exact + RiT 做最终对齐；报告时必须把课程奖励与论文 strict 口径分开。
3. 对 UNSAFE 或多标签样本提高 prompt 采样权重，并检查每个 batch 的 SAFE/UNSAFE 组成。
4. 将“是否安全”和“完整风险类别”拆成两个可诊断 reward，但最终仍用严格结果做保留集选择。
5. 增加独立 verifier 或人工审核集评测规则/Case 是否真的支持结论，而不是只检查 ID 存在。

这些是根据本次塌缩轨迹得到的实验建议，不是已经验证有效的结果。
